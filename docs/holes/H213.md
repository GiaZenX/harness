# H213 -- Die gedruckte Abhilfe des Commit-Schutzes läuft nicht, wie sie gedruckt ist (BUG-0297, OFFEN: wartet auf den Nutzer)

**Mechanismus.** Der Commit-Schutz dieses Repos (`.claude/hooks/gate_commit_evidence.py`) verweigert
einen Commit, solange kein Prüfurteil den Zustand des Arbeitsbaums nennt. Er druckt dabei die
Befehlszeile, mit der man das Urteil einträgt. Seit dieser Generation verlangt der Kernel für so
einen Eintrag zwei zusätzliche Angaben (`--run-command`, `--run-scope`; H108/BUG-0192): ein Beweis,
der nicht sagt, **was** gelaufen ist, verspricht mehr, als er misst. Der gedruckte Text wurde
vorher geschrieben und nennt die beiden nicht — wer ihn abtippt, bekommt eine Fehlermeldung des
Kommandozeilen-Parsers statt eines Eintrags. Der Schutz selbst hält; **die Anleitung** stimmt nicht.

**Warum es niemand sah:** Der Test, der diese Abhilfe angeblich prüft
(`.claude/hooks/test_gates.py::test_gate3_remedy_is_executable_and_opens_the_commit`), **baut** die
Befehlszeile selbst zusammen, statt die gedruckte zu lesen. Er misst damit, ob der Kernel die
beschriebene Form annimmt — nicht, ob die gedruckte Zeile läuft. Genau zwischen diesen beiden
Sätzen lebte der Defekt zwei Runden lang.

**Gemessene Kette** (Umsetzer C, TSK-0148, Rig `_round-scratch/TSK-0148`, 2026-09-12 23:19–23:22;
jede Zeile aus dem Verweigerungstext geparst und durch eine echte `bash` gefahren):

| Zustand von `gate_commit_evidence.py` | Ergebnis |
|---|---|
| heute (5ecf62a) | **rot** — `error: the following arguments are required: --run-command, --run-scope` |
| mit dem S4-Patch des Nutzers (nur in der Kopie) | **grün**, und der zuvor verweigerte Commit ist danach offen |
| S4-Patch, aber `--run-scope` wieder entfernt | **rot** — `error: the following arguments are required: --run-scope` |

Die dritte Zeile ist der Punkt: Der neue Test misst **jede** fehlende Pflichtangabe, nicht die zwei
von heute.

**Warum es hier niemand schließen kann.** `.claude/hooks/` ist jeder Rolle dieses Repos zum
Schreiben verwehrt — das ist Absicht: Wer den Schutz von innen reparieren darf, kann ihn von innen
abschalten. Der Patch ist zwei Zeilen lang, liegt fertig unter
`project_memory/staging/TSK-0141/s4-gate-commit-evidence-patch.md` und gehört in eine Shell
**außerhalb** von Claude Code, danach eine neue Sitzung.

**Was bis dahin gilt, ausdrücklich:**
`.claude/hooks/test_gates.py::test_gate3_prints_a_remedy_that_runs_as_printed` ist **rot** und
bleibt rot, bis der Patch gefahren ist. Das ist der gewollte Zustand für einen Defekt, dessen Fix
keine Rolle hier schreiben darf: Ein roter Test ist die ehrliche Anzeige, ein nachgereichter Test
wäre die stille. Für BUG-0297 wurde deshalb **kein** Beweis („EVD") eingetragen, der einen
Abschluss behauptet. Neben ihm steht seit TSK-0144 ein zweiter roter Test, der dieselbe Stelle von
außen misst — `tools/test_hooks.py::test_every_evidence_command_a_text_spells_names_every_argument_the_cli_requires`,
in der Kopie von 5ecf62a am 2026-09-12 23:26 als `1 failed` gemessen, mit denselben zwei Namen
darunter.

**Was der Defekt kostet, begrenzt:** Der Commit bleibt geschützt (kein Commit ohne Beweis); es
trifft nur den, der die gedruckte Zeile abtippt — der bekommt eine Fehlermeldung, die genau die
zwei fehlenden Angaben nennt, und kann sie von Hand ergänzen.
